📖 Concept

What is Git & GitHub?

Two different things. People confuse them constantly. Let's fix that.

💻

Your Machine

Where you write code & work locally

→
🔧

Git

Tracks changes, saves snapshots locally

→
☁️

GitHub

Cloud storage for your code. Shareable & backed up

🔧 Git

Git is a free tool you install on your computer. It tracks every change you make to your code — think of it like "Ctrl+Z on steroids" with a full history of every save. It runs entirely on your machine with no internet required.

🐙 GitHub

GitHub is a website where you upload your Git-tracked code to the cloud. It lets you share projects, collaborate with teams, and back up your work so you never lose it. Think Google Drive, but built for developers.

⚡ Real World

Real Errors & Exact Fixes

These are actual errors from actual pushes. Exact error text, exact cause, exact fix. Nothing made up.

ERR 1
src refspec main does not match any
Happens when: you try to push to "main" but your branch is called "master"
error: src refspec main does not match any
error: failed to push some refs to 'https://github.com/USERNAME/REPO.git'
Cause

Git defaults to a branch named "master" on older installs. GitHub defaults to "main". They don't always match. You pushed to "main" but your local branch is called "master".

✅ Fix

First, check what your branch is actually called:

cmd
git branch
# Look for the asterisk — that's your current branch name

Then push to the correct branch name:

cmd
git push -u origin master
ERR 2
HTTP 408 / RPC failed — Connection timed out mid-push
Happens when: your internet is slow or the upload is too large
error: RPC failed; HTTP 408 curl 22 The requested URL returned error: 408
send-pack: unexpected disconnect while reading sideband packet
fatal: the remote end hung up unexpectedly
Cause

Your internet connection is too slow or unstable. Git's default buffer is too small for large uploads, causing the connection to drop mid-push.

✅ Fix
Option A — Increase buffer size & retry:
cmd
git config http.postBuffer 524288000
git config http.lowSpeedLimit 0
git config http.lowSpeedTime 999999
git push -u origin master
Option B — GitHub Web Upload (most reliable for slow connections):

Go to your repo → click "uploading an existing file" → drag & drop all files → click "Commit changes". No connection issues, no buffer settings needed.

ERR 3
"Everything up-to-date" after a 408 timeout
NOT always an error — this can mean your push actually worked
Everything up-to-date
Cause

After a 408 timeout, Git may report "Everything up-to-date." This means the objects were already transferred to GitHub before the connection dropped. The push may have actually succeeded.

✅ Action

Go check your GitHub repo directly in the browser. If your files are there — you're done. Don't push again. If they're not there, then retry the push or use the web upload method.

ERR 4
cd E:\Path didn't change the drive — path stayed on C:
Windows CMD cannot switch drives with cd alone
C:\Users\samayasivam> cd E:\Portfolio\Madushan_Portfolio_QA
C:\Users\samayasivam> ← prompt did NOT change — still on C:
Cause

cd cannot switch drives in Windows CMD. When you type cd E:\path, CMD ignores the drive letter entirely and just tries to navigate on the current drive.

✅ Fix — Two commands, not one:
cmd — correct way
# Step 1: Switch to the drive first
E:

# Step 2: Then navigate
cd Portfolio\Madushan_Portfolio_QA

# ❌ WRONG — This does NOT work:
cd E:\Portfolio\Madushan_Portfolio_QA

🌐 Free Hosting

GitHub Pages — Host Your Site for Free

GitHub Pages turns any public repo into a live website. No server. No cost. No maintenance. Perfect for portfolios and static sites.

# Your live site URL will be:
https://YOUR-USERNAME.github.io/REPO-NAME
# Personal site (repo must be named username.github.io):
https://username.github.io
# Project site (any repo name):
https://username.github.io/repo-name
1

Make sure your repo is Public

GitHub Pages requires a public repo on free accounts. Go to your repo → Settings → scroll down → "Danger Zone" → Change visibility to Public.

2

Go to Settings → Pages

In your repo, click the Settings tab → In the left sidebar, click Pages.

3

Set Source Branch

Under "Build and deployment": Source → Deploy from a branch → Branch: master (or "main" if that's what you used) → Folder: / (root) → Click Save.

4

Wait and Visit

GitHub takes up to 10 minutes to build and deploy. Check the Actions tab in your repo to see deployment progress. Then visit: https://YOUR-USERNAME.github.io/REPO-NAME

5

Update Your Site Anytime

GitHub Pages automatically rebuilds every time you push. No manual deploy needed — just push and it updates.

cmd
git add .
git commit -m "update site"
git push

⚠️ Important Limitations

  • Only static sites (HTML, CSS, JS). No PHP, no Node.js server, no databases.
  • Private repos need GitHub Pro for Pages.
  • Max site size: 1GB. Max bandwidth: 100GB/month.
  • Build timeout: 10 minutes per deployment.

👥 Teams

Teams & Members

Teams are groups within an organization — they mirror real-world departments and control who can access what.

Organization: MyCompany
├── Team: Engineering (Write access to all repos)
│ ├── Frontend (Write → frontend repos)
│ │ ├── React-Team
│ │ └── CSS-Team
│ ├── Backend (Write → backend repos)
│ └── DevOps (Admin → infrastructure repos)
└── Team: QA-Team (Read access to all repos)
Child teams INHERIT parent team permissions. Engineering's access flows down to all its child teams.

🌿 Branching & PRs

Branching & Pull Requests

Never work directly on master. Branches let you build features in isolation. PRs let teams review before code merges. This is how real teams ship.

🌿
Rule #1: NEVER work directly on master or main for real projects. Create a branch for every feature or fix.

Branch Commands — Full Reference

bash
git branch                        # List all local branches (* = current)
git branch -a                     # List all branches (local + remote)
git branch feature-login          # Create a new branch (stay on current)
git checkout feature-login        # Switch to that branch
git checkout -b feature-login     # Create AND switch in one command (shortcut)
git branch -d feature-login       # Delete branch (safe — won't delete if unmerged)
git branch -D feature-login       # Force delete (even if unmerged)
git branch -m old-name new-name   # Rename a branch
git push origin feature-login     # Push branch to GitHub
git push origin --delete feature-login  # Delete remote branch

Standard Branch Workflow — How Professionals Do It

1

Start from an updated master

Always start from the latest version of master before creating a branch.

2

Create a branch for your feature

Use a descriptive name. One branch per feature or fix.

3

Do your work, then commit

Make changes, stage them, commit with a clear message.

4

Push your branch to GitHub

Upload the branch so GitHub knows about it.

5

Create a Pull Request on GitHub

GitHub shows a "Compare & pull request" banner — click it. Write what the PR does and why.

6

After review — merge the PR

Reviewers approve, you merge. The code is now in master.

7

Clean up — delete the branch

Pull the updated master and delete the feature branch locally.

bash — full workflow
# 1. Make sure you're on master and it's up to date
git checkout master
git pull origin master

# 2. Create a new branch for your feature
git checkout -b feature-navbar

# 3. Do your work, then commit
git add .
git commit -m "Add responsive navbar"

# 4. Push your branch to GitHub
git push -u origin feature-navbar

# 5. On GitHub — create a Pull Request (PR)
# Go to your repo → "Compare & pull request" banner → Click it
# Write description → Click "Create pull request"

# 6. After review — merge the PR on GitHub

# 7. Come back to CMD and clean up
git checkout master
git pull origin master
git branch -d feature-navbar

Merge Conflicts — What They Are & How to Fix Them

A conflict happens when two people change the same line in the same file in different branches. Git can't decide which version to keep — it stops and asks you to fix it manually.

When you open a conflicted file, you'll see this:

<<<<<<< HEAD
Your version of the line (what's in your current branch)
=======
Their version of the line (what's in the branch you're merging)
>>>>>>> feature-branch
bash — fix a conflict
# 1. Git tells you there's a conflict when you merge
git merge feature-branch
# OUTPUT: CONFLICT (content): Merge conflict in index.html

# 2. Check which files have conflicts
git status

# 3. Open the conflicted file in your editor
#    Find <<<<<<< markers
#    Decide which version to keep (yours, theirs, or combine both)
#    DELETE all conflict markers (<<<<<<<, =======, >>>>>>>)

# 4. Stage the resolved file
git add index.html

# 5. Complete the merge
git commit -m "Resolve merge conflict in index.html"
Prevention tips: Pull before you start working (git pull origin master). Keep branches short-lived — merge often, don't let them diverge for weeks. Communicate with teammates about who's touching which files.

🛡️ System Health

System Repair: DISM & SFC

Windows acting weird? Corrupted files? Here's how to fix it the right way.

⚠️
Run CMD as Administrator — right-click CMD → "Run as administrator". These commands won't work without elevated privileges.

DISM Higher Level

  • Repairs the Windows OS image itself
  • Connects to Windows Update to get clean files
  • Run this FIRST, before SFC
  • Takes 10–30 minutes (normal to stall at 20%)
  • Required if SFC fails or keeps failing

SFC File Level

  • Scans and repairs protected system files
  • Works from the repaired image DISM creates
  • Run this AFTER DISM completes
  • Usually takes 5–15 minutes
  • Fixes blue screens, missing DLLs, crashing apps
1

DISM CheckHealth — Quick check

Fast scan to see if the image is flagged as corrupt. Doesn't fix anything.

cmd (Admin)
DISM /Online /Cleanup-Image /CheckHealth
2

DISM ScanHealth — Deeper scan

More thorough. Scans for corruption but still doesn't repair.

cmd (Admin)
DISM /Online /Cleanup-Image /ScanHealth
3

DISM RestoreHealth — Actually fixes it

Downloads clean files from Windows Update and repairs corruption. 15–30 min. Don't panic if it stalls at 20% or 62% — that's completely normal.

cmd (Admin)
DISM /Online /Cleanup-Image /RestoreHealth
4

SFC /scannow — Repair system files

Now that DISM fixed the image, SFC repairs individual corrupted files. Restart when it finishes.

cmd (Admin)
sfc /scannow
📀 Offline Repair (when internet fails): Download a Windows ISO from microsoft.com, mount it (double-click), note its drive letter, then run:

DISM /Online /Cleanup-Image /RestoreHealth /Source:D:\Sources\install.wim
Replace D: with your ISO's actual drive letter.
🧠 Power User

Pro Tips

Small things that save you massive time. Use them daily.

⇥

Tab Completion

Start typing a folder name and press Tab to autocomplete. Press Tab multiple times to cycle through matches. Saves half your typing.

↑↓

Command History

Press ↑ and ↓ arrow keys to cycle through previously typed commands. Stop retyping the same thing.

🔐

Run as Administrator

For DISM, SFC, and system-level commands: right-click CMD or PowerShell and select "Run as administrator". Without this, half the commands are blocked.

❓

Built-in Help System

Add /? to any command for all options: ipconfig /?  git --help. Works for everything.

🚫

Use .gitignore

Create a .gitignore file in your project root. List node_modules/, .env, .DS_Store, *.log. Git will never track those files. Never push passwords or API keys.

⚡

Git Aliases

Set up shortcuts:
git config --global alias.s "status"
git config --global alias.lg "log --oneline --graph --all"
Now git s runs status.

↩️

Safe Undo in Git

Undo last commit but keep files: git reset --soft HEAD~1
Stash work temporarily: git stash
Bring it back: git stash pop

⚡

PowerShell > CMD

For advanced tasks, use PowerShell instead of CMD. It supports the same commands PLUS scripting, loops, and more. Open via Win+R → powershell.
